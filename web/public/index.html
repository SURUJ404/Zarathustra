What is it

Zero-knowledge proofs, simplified

Astra lets you write a circuit like a normal Python-ish program and produce a real, verifiable zero-knowledge proof — without writing any constraint systems by hand.

A zero-knowledge proof convinces a verifier that a statement is true (e.g. "I know a secret x such that x + y == 7") without revealing what x is. Building those proofs has historically required deep cryptographic expertise. Astra removes that barrier by providing:

  • A readable, typed, imperative language (Zara) with assert-based constraints.
  • A full pipeline: compile → setup → prove → verify powered by ark-groth16 on BLS12-381.
  • Static security analysis that flags unsafe circuits and Solidity verifiers before you ship.
  • A browser-native WASM surface and an in-browser playground.

Example circuit — prove knowledge of x such that x + y == sum

// Prove you know x, y such that x + y == sum
def main(field public sum, field private x, field private y) -> field {
    assert(x + y == sum);
    return 1;
}
Why

Why Zara

Astra's goal is broad feature parity with — and eventually to overtake — ZoKrates: friendly syntax, multiple proof backends, static security analysis, and first-class deployment of verifiers.

  • Readable. Imperative, typed, assert-based constraints — no raw R1CS.
  • Structured errors. Parse and compile diagnostics carry source spans, so errors point at the actual line.
  • Built for tooling. An LSP hook (DocumentService) and a browser-native WASM frontend ship in the repo.
  • Security-first. A built-in auditor runs signal-flow and CEI/reentrancy analysis.

Workspace crates

CrateRole
astra_irCore IR: AST, R1CS, Plonkish-first Constraint kinds. Free of proof crypto so it's portable across backends.
astra_frontendZara lexer/parser, span-aware errors, LSP hook, browser-native WASM bindings.
astra_codegenLowers Zara to R1CS + witness; defines the Backend trait.
astra_proverProof-system registry: ark-groth16 (default) + hand-rolled reference (legacy).
astra_stdlibVersioned gadget library (hash / signature / commitment / snark / primitive).
astra_publishVerifier export: EVM, Starknet, WASM, Aleo, JSON test vectors.
astra_securityStatic analyzers: signal flow, CEI/reentrancy, pattern checks (CIR-001..006, SOL-001..006).
astra_cliThe astra binary — a thin clap interface over the layers.

Boundaries

  • astra_ir stays free of any proof-system crypto so the IR is portable across backends.
  • astra_frontend owns the grammar, source-span errors, the LSP hook, and the WASM surface.
  • astra_codegen lowers Zara → R1CS/witness and defines Backend.
  • astra_prover registers proof systems (ark-groth16 default; legacy.rs kept as audit reference).
  • astra_publish exposes VerifierTarget skeletons that return Err("... not yet implemented in v0.0") instead of emitting a fake verifier.
  • astra_security runs deterministic static analysis.
  • astra_cli is a thin binary over the layers.
Quickstart

Get started in minutes

Install

Build the workspace and the astra CLI:

$ cargo build --workspace --release
$ cargo test --workspace   # optional, run the suite

Run the full proof pipeline

  1. Compile Zara → R1CS + witness.
    $ astra prove compile -p 8 -r 3,5 examples/sum.zara
  2. Setup — generate the CRS (pk.json, vk.json):
    $ astra prove setup -p 8 -r 3,5 examples/sum.zara
  3. Prove — produce proof.json:
    $ astra prove prove -p 8 -r 3,5 examples/sum.zara
  4. Verify — validate the proof (exit 0 / 1):
    $ astra prove verify -p 8 -r 3,5 examples/sum.zara
∞  PROOF VERIFIED

All artifacts drop into the current working directory: pk.json, vk.json, proof.json.

Security audit

$ astra audit .                            # terminal report
$ astra audit --format json -o audit.json .
$ astra audit --deny high .               # exit non-zero on HIGH+ findings

Check IDs: CIR-001..006 (circuits) and SOL-001..006 (Solidity). Includes a signal-flow analysis that flags unconstrained public inputs at HIGH severity and a CEI / reentrancy check for Solidity verifiers.

Playground

In-browser editor

web/public/playground.html is a Monaco-based IDE. It loads the same engine your local CLI uses, but in the browser.

WASM vs API backend

IndicatorMeaning
🟢 WASM nativeThe WASM bundle (pkg/astra_frontend.js) compiled in the browser — no server required.
⚪ WASM unavailable (API fallback)No WASM bundle found; compile falls back to the /api/* backend.
🟢 Backend OKThe API reachable; the astra binary is present on the server.
  • Compile runs natively in the browser when the WASM bundle is present; otherwise via the API.
  • Prove / verify currently require the backend — Groth16 is not WASM-safe yet.

Build the WASM bundle

$ cargo build -p astra_frontend --target wasm32-unknown-unknown --release --features wasm
$ cp target/wasm32-unknown-unknown/release/astra_frontend.wasm web/public/pkg/astra_frontend_bg.wasm
Projects & publishing

Scaffold and deploy

Project scaffolding

$ astra deploy init project          # creates project/src/main.zara
$ astra deploy verifier              # Solidity export (errors out for now)
$ astra deploy verify                # simulated on-chain verify (pending)

Verifier publishing

$ astra publish -t jt                # → zara_test_vectors.json (real proof + VK)
$ astra publish -t evm                # BLS12-381 refuses; BN254 verifier pending
