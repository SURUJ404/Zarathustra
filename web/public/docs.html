CLI Documentation

The Astra toolchain: Zara DSL, Groth16 proving, auditing, and publishing.

Every pipeline command operates on Zara (`.zara`) source files and writes artifacts to the current working directory: pk.json, vk.json, proof.json. Run astra <cmd> --help for exact usage on your machine.

Command Description
prove compile Compile a .zara file into R1CS + witness
prove setup Generate the CRS: writes pk.json + vk.json
prove prove Generate a Groth16 proof: writes proof.json
prove verify Honestly verify proof.json against vk.json + bound public inputs
audit Static security scan of circuits and Solidity verifiers
deploy init Scaffold a new circuit project
deploy verifier Solidity verifier export (errors out until real EVM export lands)
publish Export test vectors / verifiers for target platforms

Command Reference

prove compile

▾

Description

Compiles a .zara source file into a constraint system (R1CS), evaluates the witness, and prints the circuit summary.

Usage

$ astra prove compile [OPTIONS] <input>

Options

  • <input> — Source file (required)
  • -p, --public — Comma-separated public inputs
  • -r, --private — Comma-separated private inputs

Example

$ astra prove compile -p 8 -r 3,5 examples/sum.zara
=== Circuit ===
  Variables:   4
  Public:      2
  Private:     2
  Constraints: 1

prove setup

▾

Description

Generates the trusted setup (CRS) for the circuit. Writes pk.json and vk.json.

Usage

$ astra prove setup [OPTIONS] <input>

Options

  • <input> — Source file (required)
  • -p, --public — Comma-separated public inputs
  • -r, --private — Comma-separated private inputs
  • --backend — ark-groth16 (default) or legacy

Example

$ astra prove setup -p 8 -r 3,5 examples/sum.zara
=== Trusted Setup Complete ===
  Backend:     ark-groth16
  Curve:       bls12-381
  Wrote pk.json, vk.json

prove prove

▾

Description

Generates a Groth16 proof and writes proof.json, binding the public inputs into it.

Usage

$ astra prove prove [OPTIONS] <input>

Options

  • <input> — Source file (required)
  • -p, --public — Comma-separated public inputs
  • -r, --private — Comma-separated private inputs
  • --backend — ark-groth16 (default) or legacy

Example

$ astra prove prove -p 8 -r 3,5 examples/sum.zara
=== Proof Generated ===
  Backend:     ark-groth16
  Curve:       bls12-381
  Saved to proof.json

prove verify

▾

Description

Verifies proof.json against vk.json and the public inputs bound into the proof. Refuses tampered proofs or mismatched keys with a non-zero exit.

Usage

$ astra prove verify [OPTIONS] [input]

Options

  • [input] — Source file (kept for CLI compatibility; verify reads proof.json)
  • -p, --public — Public inputs (validated against the bound ones)
  • --backend — ark-groth16 (default) or legacy

Example

$ astra prove verify examples/sum.zara
=== Verification ===
  Backend:      ark-groth16
  Proof:        ./proof.json
  ✓ PROOF VERIFIED

audit

▾

Description

Static security scan of circuits and smart contracts. Includes a signal-flow analysis that flags unconstrained public inputs, plus CEI/reentrancy checks for Solidity.

Usage

$ astra audit [FLAGS] [OPTIONS] [target]

Options

  • [target] — File or directory to scan (default .)
  • -v, --verbose — Verbose output
  • -f, --format — terminal | json | html (default terminal)
  • -o, --output — Write the report to a file
  • --deny — critical | high | medium | any; exit non-zero if findings at/above severity

Example

$ astra audit --format json -o audit.json .
=== Security Scan Complete ===

deploy init

▾

Description

Scaffolds a new circuit project with a starter src/main.zara.

Usage

$ astra deploy init <name>

Example

$ astra deploy init my-circuit
Initialized project: my-circuit
  my-circuit/src/main.zara - circuit source

deploy verifier

▾

Description

Export a Solidity verifier. This is honest-by-default: rather than emitting a stub contract that always returns true, it errors out with guidance to use astra publish -t evm once that lands.

Usage

$ astra deploy verifier

publish

▾

Description

Exports verifiers / test vectors for target platforms.

Usage

$ astra publish [OPTIONS]

Options

  • -t, --target — evm | starknet | wasm | aleo | jt (default evm)

Details

  • jt — reads proof.json + vk.json, writes zara_test_vectors.json with real artifacts
  • evm — honestly refuses BLS12-381 (no Ethereum pairing precompile); meaningful only for BN254
  • starknet, wasm, aleo — not yet implemented

Example

$ astra publish -t jt
publish: wrote zara_test_vectors.json
  curve:    bls12-381
  protocol: groth16
